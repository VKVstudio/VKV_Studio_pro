# Local editorial draft scaffold

`editorial-draft.workflow.json` is an importable **inactive** n8n workflow. It has a manual trigger, a replaceable sample candidate, exact-candidate cloud attestation, one fixed OpenRouter request, strict response validation, and an **unverified** manual-review artifact in the execution output. Its fixture has consent flags set to `false` and cannot reach the paid request as imported. It does not call the editorial backend, write a story, approve a digest, export content, publish, deploy, or post socially. No webhook is present.

## Local checks

From this directory run `node build-workflow.mjs` to regenerate the workflow JSON from the two reviewed Code-node files, then `node test-workflow.mjs`. These checks execute both embedded validators against valid and hostile fixtures without n8n, credentials, network, or new packages. They do not prove compatibility with an installed n8n instance or the selected provider endpoint.

## Configuration before a first paid manual run

1. Install and secure a private n8n instance separately, then import the JSON and keep the workflow inactive. This repository has not installed or started n8n.
2. In n8n, create a **Header Auth** credential named for OpenRouter, with header name `Authorization` and value `Bearer <private API key>`. Select that credential on `OpenRouter draft request`. Keep the key out of this file, the workflow export, input JSON, and execution logs. Restrict who can view or edit this workflow and its execution data.
3. Check that `deepseek/deepseek-v4-flash-0731` still exists, supports JSON object output, and fits the intended price. Set a small **OpenRouter account credit/budget limit** and verify provider routing and retention terms. The workflow rejects a serialized UTF-8 request of 2,500 bytes or more **before** the HTTP node, caps model output at 900 tokens, and rejects responses reporting over 3,000 input tokens. These are conservative volume limits, **not** a guaranteed dollar cap. It has one request per manual execution and no retry path. Do not bulk-run or retry failed executions automatically.
4. Have a human select a public, official **primary** article from exactly one of these HTTPS hosts: `mistral.ai`, `developers.google.com`, `developers.googleblog.com`, `blog.google`, `openai.com`, `developer.nvidia.com`, `blogs.nvidia.com`. The hostname check is exact; a page must have a non-root path. The private backend must fetch and normalize sources itself with redirect, size and time limits. Do not use client/private material, scraped private pages, or unreviewed HTML. This is a **human source and cloud-use attestation**, not automated PII detection. The URL check cannot tell whether copied text contains private information.
5. Replace the `candidate` object in `Input candidate (replace fixture locally)` with the exact eight fields from `backend/editorial.py` v2. To calculate the digest, save only that candidate as a **local** JSON file and run `node candidate-digest.mjs <local-candidate.json>`; the helper only prints SHA-256 and sends nothing. Enter that digest in `attestation.candidateSha256`, and set `publicPrimarySource` and `cloudUseApproved` to `true` only after checking the exact candidate content and intended external provider use. Changing any candidate field invalidates this attestation. Caller-supplied callback URLs, commands, model IDs, or other fields are rejected.
6. Execute manually on a small, public-safe candidate. Inspect the final `unverified-manual-review-required` artifact. `unverifiedClaimSuggestions` and `unverifiedDraftSections` are suggestions only: quote substring presence does **not** establish that a source entails the claim or that the context is fair. A human must reopen the primary source, verify meaning and context, separately construct the reviewed ledger, edit and validate the full v2 article in `backend/editorial.py`, and obtain Valerii Karpov's separate exact digest approval before any export. A workflow success is not approval.

## Private worker handoff is deliberately pending

The final n8n item is the handoff artifact. A private worker integration needs a separately designed authenticated endpoint, authorization scope limited to a draft proposal, replay protection, request size limits, and backend-side validation before any network handoff can be enabled. There is no callback URL field, webhook trigger, HTTP handoff node, or public endpoint in this scaffold. The existing CLI has no private HTTP handoff API. Adding one and enabling any external trigger requires its own review.

## Security review

Untrusted boundaries are the replaceable candidate and model response. Exact field sets, official-host checks, exact-candidate SHA-256 attestation, pre-charge UTF-8 request size, support-substring checks, token usage checks, and a fixed model/endpoint prevent incoming data from choosing a network destination, command, or provider model. Attestation is a human decision and can be falsely asserted by someone with workflow edit/run access; restrict that access. The source quotation may still be misleading or out of context; the substring check only proves occurrence in the supplied excerpt. The source excerpt itself needs a trusted backend fetch, and the complete v2 article requires human semantic review and backend validation. Execution output contains draft text; protect and prune n8n execution records under the private instance's retention policy. No secret literals or approval credentials are stored here.
